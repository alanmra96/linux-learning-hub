Users &
Groups.

Linux uses identities to decide who is running a command and which resources they can use. Meet users, groups, and the numeric IDs behind both.

12 min read Beginner level 3 commands
ID
THE MENTAL MODEL

Identity first, access second.

A user identifies one account. Groups collect users who need something in common, such as access to a shared project. Linux checks that identity and the resource's permissions together.

maya → developers → project-plan.md
THE BUILDING BLOCKS

Names for people.
Numbers for Linux.

Friendly names are easier to remember, but Linux tracks users and groups with numeric identifiers behind the scenes.

01

User and UID

A user is an identity that can own files and run processes. Its UID is the numeric user identifier Linux uses internally.

maya → UID 1000
02

Group and GID

A group collects identities for shared access. Its GID is the group's numeric identifier.

developers → GID 2000
03

Primary and supplementary

Every user has one primary group, commonly used for new files, and can belong to additional supplementary groups.

maya + developers
04

The root user

root is the administrative user with UID 0. It can bypass ordinary permission checks, so it should be used carefully—not as an everyday account.

root → UID 0
THREE SAFE QUESTIONS

Ask Linux who you are.

whoami
Print the name of the current user.
id
Show the current user's UID, primary GID, and groups.
groups
List the groups the current user belongs to.

KEY TAKEAWAY

Identity connects to access.

Commands such as whoami, id, and groups reveal the identity Linux uses. Group membership can grant shared access, but the resource's ownership and permissions still decide what that group may do.
